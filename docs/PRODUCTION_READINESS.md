# 本番相当ペーパー運用の状態

更新日: 2026-08-07

## 現在できること

- bitbank、GMOコイン、bitFlyer、Coincheckの公開板を同時取得する。
- 取得失敗時は、データ種別を明示して模擬板へ切り替える。
- 手数料、スリッページ、再配分予備費を控除した裁定候補を計算する。
- 取引所ごとにJPY/BTCを事前配置したペーパー残高から両側同時約定を計算する。
- SQLiteへ残高、約定、エクイティ、イベント、設定を保存する。
- 総資産、日次/累積損益、年率収益率、ボラティリティ、Sharpe、Sortino、最大ドローダウン、Calmar、勝率、Profit Factor、実行コストを表示する。
- 初回起動時に30日分の明示的なデモ履歴を投入し、画面をすぐ評価できる状態にする。
- APIキーの登録場所と必要な環境変数を表示する。ただしキー値は保存・返却しない。
- ペーパー運用の開始、停止、1サイクル実行、停止スイッチ、閾値変更をWeb画面から行う。

## 意図的にできないこと

- 取引所へ実注文を送ること。
- 暗号資産や法定通貨を出金すること。
- ブラウザからAPIキーをサーバーへ保存すること。
- リモート公開時のユーザー認証、TLS終端、監査ログ署名。

## データの見分け方

| `source` | 意味 |
|---|---|
| `seeded_research_demo` | 初期表示用の決定論的な30日デモ |
| `live_public_orderbooks` | 取引所の公開板を利用したペーパー判定 |
| `simulated_research_snapshot` | 公開板が2社未満の際に使う模擬スナップショット |

画面では常に `SIMULATED / 実注文なし` と表示します。初期デモ実績を実績収益として扱ってはいけません。

## 本番前の残課題

- 認証付き残高参照アダプターと取引所残高照合。
- 各取引所の最小注文、数量刻み、価格刻み、メンテナンス時間の強制検証。
- WebSocket板と板シーケンス整合性。
- 部分約定、片側失敗、キャンセル失敗時の状態機械。
- 日次損失、連続損失、APIエラー率、約定遅延による自動停止。
- 資金移動コストと再配分所要時間を含む収益判定。
- 外部公開する場合のOIDCまたはVPN、TLS、CSRF対策、監査ログ。
- 実運用用データベースのバックアップ、復旧訓練、時刻同期。

## 起動

### Python

```bash
cp .env.example .env
python -m venv .venv
. .venv/bin/activate
pip install -e '.[dev,web]'
arbweb
```

既定URLは `http://127.0.0.1:8000` です。

### Docker Compose

```bash
docker compose up --build
```

ホスト側は `127.0.0.1:8000` のみに公開され、SQLiteはDocker volumeへ保存されます。

## 受入条件

少額実運用へ移る判断は、最低でも次を満たした後に行います。

- 7日以上の連続ペーパー稼働。
- 公開板取得成功率99%以上。
- 手数料・数量刻みを含むshadow orderの一致率100%。
- 片側約定テストから規定時間内に復旧できること。
- 日次損失上限、総資金上限、停止スイッチの実地確認。
- 取引所残高と台帳が日次で一致すること。
